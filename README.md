# LUMEN

Генератор синтетических UI-дефектов и пар скриншотов для анализа изменений интерфейса.

- INSPECT: изображение и координаты дефектов.
- DIFF: изображения до и после изменения, разметка и маска изменённых пикселей.
- Экспорт: YOLO, COCO, JSONL для Hugging Face Datasets.
- Дополнительные аннотации: элементы, состояния и взаимодействия.

TypeScript, Playwright, Python, OpenCV, SQLite.

```sh
docker build -t lumen-data .
docker run --rm --init lumen-data lumen-data --help
```

Команды CLI: `sources`, `generate`, `qa`, `review`, `export`, `reproduce`.

Обход публичных сайтов: `node --experimental-strip-types browser/collector.ts CONFIG.json OUTPUT`.
Требуются Linux с `flock` и установленные npm-зависимости. Конфигурация:

```json
{"seeds":[{"id":"example","url":"https://example.com/","scope":"/","family":"content","allowed_hosts":["example.com"],"license":"unknown"}],"max_pages_per_project":5,"max_depth":1,"concurrency":2,"requests_per_minute":20,"domain_delay_seconds":2}
```

Сборщик выполняет JS, сохраняет ресурсы и принимает только точное offline-воспроизведение.
Обход учитывает robots.txt, ограничен origin и `scope`; query, fragment и маршруты выхода/удаления
не обходятся. Повторные попытки отключены. `allowed_hosts` задаёт точные HTTPS-hosts ресурсов;
нестандартный порт разрешён только вместе с host в этом списке. Все маршруты проекта имеют
общий `split_group`. Результат `manifest.jsonl` подключается как `source_manifest`,
а `OUTPUT/assets` — через `LUMEN_ASSET_ROOT`. Источники остаются `research_only` и `unclassified`.
Повторный запуск с той же конфигурацией и версией кода восстанавливает очередь и manifest.
Число зарезервированных URL, включая robots-отказы, ограничено `max_pages_per_project`.

`capturePreparedPage(page, request)` применяет те же мутации к уже загруженному приложению,
сохраняя canvas и JS-состояние. Новые сетевые запросы блокируются на время мутации;
baseline и откат должны совпасть точно. При неподтверждённом откате страница закрывается.
Результат помечается `capture_mode: live-session` и не подтверждает независимый offline replay.

В конфигурации генерации `operators` задаёт список операторов; повторения задают веса.
Список и его порядок фиксируются для `resume`. Без списка используется встроенный каталог.
`source_mix: [grammar, grammar, external]` задаёт пропорцию попыток для собственных
и подготовленных внешних сцен; `external` требует `source_manifest`. Список фиксируется для `resume`.
`viewport_sweep` задаёт состояния `{viewport: [390, 844], dpr: 2}`. Каждый вариант
мутации повторяется во всех состояниях с неизменными HTML, идентичностью сцены и split.
Необязательный `resize_path: [[1280, 720], [844, 390]]` меняет размер уже открытой
страницы перед финальным `viewport`. Поддерживаются DPR 1/2, до 64 состояний и 8 шагов.
Ориентация определяется размерами viewport. По умолчанию JavaScript отключён.
Источники с `render_mode: offline-js` исполняют JS с фиксированными часами и seed,
окном инициализации 1000 мс и 100 мс на шаг resize; затем таймеры приостановлены.
Доступны только локальные ресурсы с проверкой SHA-256. Ошибки JS и недостающие
ресурсы отклоняют пример. Запускайте обработку недоверенных источников в отдельном
контейнере с `--init`, без сети, секретов и доступа к файловой системе хоста.
`--init` необходим для сбора завершившихся дочерних процессов Chromium.
Превышение общего бюджета capture (45 секунд) учитывается отдельно как `render_timeout`;
оно не доказывает дефект исходного интерфейса. Остальные ошибки браузера останавливают запуск.
`breakpoint_shift_regression` ищет поломку при сдвиге `min/max-width/height` в px
не более чем на 64 px; другие формы media queries не покрываются этим оператором.
`resize_stale_width_regression` требует `resize_path` и моделирует сохранённую ширину
контейнера, которая не обновилась после resize. Это синтетика, а не запуск JS обработчика страницы.
Механизм мутации хранится отдельно от симптомов, подтверждённых browser-валидатором.

`benign_near_boundary` сохраняет последнее допустимое состояние перед подтверждённой
поломкой; `benign_composite_control` — безопасный компонент составного сценария.
Рецепт содержит `control_of` и, для составного сценария, `control_component` (0 или 1).
Составные сценарии принимаются только при корректности обоих компонентов по отдельности.

`corpus` разделяет `lumen-synth` и `lumen-modern`; `defect_origin` описывает происхождение
мутации независимо от лицензии исходной страницы. Старые источники без классификации
учитываются как `unclassified`.


Импорт WebUI: `sources webui --snapshot SNAPSHOT --output OUTPUT --revision COMMIT_SHA`.
Используется `ronantakizawa/webui`, отдельно от WebUI-350k. Архив сохраняет все viewport;
manifest содержит desktop-код одной базовой сцены на `sample_id`. Источники группируются
по hostname, а upstream split сохраняется в provenance. Импорт не подтверждает качество рендера.

`sources verify --manifest MANIFEST --assets ASSETS --references REFERENCES --output OUTPUT`
проверяет чистый рендер, точное повторение и соответствие исходному screenshot.
Эвристический порог: средняя абсолютная RGB-разница не выше 0,04 от 255,
доля пикселей с разницей любого канала больше 32 — не выше 10%. Это фильтр
реконструкции, не оценка современности дизайна и не замена визуальной проверки.
`--workers` ограничивает параллелизм (1–4); `--limit` ограничивает число исходных строк.

Для потокового отбора WebCode2M установите optional зависимости: `uv sync --extra corpus`.
`sources select-webcode --output OUTPUT --revision COMMIT_SHA --max-shards 128`
читает только колонки HTML и оценки через HTTP Range. Без `--max-shards` проходит все шарды.
`--min-score` задаёт минимальную upstream оценку (2–5, по умолчанию 2) и фиксируется
для resume. Шарды, целиком ниже порога по parquet-статистике, пропускаются без чтения HTML.
Высокая оценка не заменяет визуальную проверку и не подтверждает современность дизайна.
`--per-stratum` ограничивает отбор на сочетание структуры и layout (по умолчанию 2000).
Выбор детерминирован по хешу; несовместимый HTML и внешние ресурсы отклоняются.
Результат требует browser-проверки перед обучением. Старые источники не изменяются.

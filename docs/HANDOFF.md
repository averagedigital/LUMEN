# Handoff

## Цель

Независимый пилот из 5000 accepted cases после исправления группировки, расширения структур UI и проверяемых дефектов. После подготовки ручного review остановиться. Запуски 100k, обучение и публикация датасета запрещены до отдельного решения владельца.

## Подтверждённые проблемы

- `renderable.py` присваивает WebSight `template_lineage_id = source_id`; весь источник оказывается в одной split-группе.
- Последовательность открывающих HTML-тегов недостаточна для группировки структурных копий.
- Собственная грамматика имеет общие компоненты и ограниченное число независимых шаблонов. Наличие train/val/test само по себе не подтверждает репрезентативность.
- Валидатор преимущественно анализирует текст; пять операторов не покрывают требуемые компоненты и ресурсы.

## Порядок работ

1. Regression-тесты и исправление структурной группировки. Разделить source, lineage, family, base scene и split group; измерить независимые группы на существующих WebSight-кандидатах. Проверить структурные и визуальные near-duplicates между split.
2. Расширить независимые layouts, состояния и hard negatives. Новые операторы допускать только после baseline, видимого независимого oracle, bbox, replay и похожего корректного negative. Цель: 15–20 проверенных операторов.
3. Создать новый пилот на 5000 с контролем распределений. Выполнить полный QA и подготовить стратифицированный HTML review на 500–1000 случаев. Проверить открытие изображений и сохранение решений.
4. Передать владельцу пути, команды и измеренные результаты. Не переходить к следующей фазе.
